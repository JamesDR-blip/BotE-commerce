## Seven historical server-default differences

The following seven fields have persistent server defaults in the tracked migration history. The canonical target intentionally removes those defaults under the owner policy. Each is classified as `INTENTIONAL_BEHAVIOR_CHANGE`: ORM writes that omit the field retain the application default, while direct SQL or other non-ORM inserts must now supply it. No supported non-ORM writer has been identified, and the owner explicitly chose application ownership unless a database invariant requires a server default. This changes historical direct-SQL behavior but does not change existing application-side defaults. No production data exists; local database files remain subject to the separate preserve-until-inspected rule.
