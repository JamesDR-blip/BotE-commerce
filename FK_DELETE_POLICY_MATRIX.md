## Reviewed cascade candidates — no database exceptions selected

| Candidate FK | Why CASCADE was considered | Decision and NO ACTION consequence |
|---|---|---|---|
| `organization_quotas.organization_id` | Organization-owned quota configuration; ORM `delete-orphan`. | Resolved by policy to NO ACTION. No runtime deletion path requires database cascade; an organization delete with quota children is rejected until children are explicitly removed. |
| `role_permissions.role_id` | Role-owned association rows; ORM `delete-orphan`. | Resolved by policy to NO ACTION. No role-delete runtime path requires database cascade; a role delete with links is rejected until links are explicitly removed. |
| `role_permissions.permission_id` | Permission-owned association rows; ORM `delete-orphan`. | Resolved by policy to NO ACTION. No permission-delete runtime path requires database cascade; a permission delete with links is rejected until links are explicitly removed. |

All other 40 FKs are individually inventoried above and retain the same default policy, including nullable provenance FKs and audit/lineage/execution history. Migration declarations omit `ondelete`, so their current PostgreSQL creation behavior is also NO ACTION. No database tests were run; existing SQLite ORM fixtures do not prove PostgreSQL action behavior.
